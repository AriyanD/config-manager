# هاب مدیریت اشتراک V2Ray و Xray

[نسخه انگلیسی README](README.md)

یک ابزار خودمیزبان برای **مدیریت و ترکیب کانفیگ‌ها و لینک‌های اشتراک V2Ray/Xray** که روی Cloudflare Workers اجرا می‌شود. این پروژه یک داشبورد تحت وب با رمز عبور ارائه می‌کند؛ می‌توانید کانفیگ‌ها را در گروه‌های مختلف مرتب کنید و در نهایت یک لینک اشتراک ترکیبی برای کلاینت خود بسازید.

![پیش‌نمایش رابط کاربری](assets/interface-preview.svg)

> این تصویر، پیش‌نمایش گرافیکی رابط کاربری است و از یک نشست زنده ثبت نشده است. برای دیدن داشبورد واقعی، ابتدا پروژه را طبق راهنمای زیر روی Cloudflare مستقر کنید.

## قابلیت‌ها

- **داشبورد محافظت‌شده با رمز عبور** برای مدیریت گروه‌ها و تنظیمات.
- **پشتیبانی از ورودی‌های مختلف:** افزودن مستقیم URI کانفیگ‌ها یا استفاده از یک یا چند لینک اشتراک بالادستی در هر گروه.
- **ترتیب‌دهی گروه‌ها:** جابه‌جایی با کشیدن و رها کردن یا کنترل‌های بالا و پایین.
- **چرخش ترکیبی کانفیگ‌ها:** انتخاب تعداد کانفیگ‌هایی که در هر دور از هر گروه برداشته می‌شوند.
- **دریافت زنده اشتراک‌ها و استفاده از حافظهٔ نهان:** در صورت خطا در دریافت اطلاعات، کانفیگ‌های ذخیره‌شدهٔ قبلی می‌توانند استفاده شوند.
- **ساخت یک لینک اشتراک واحد** با خروجی Base64 و امکان مشاهدهٔ متن خام برای عیب‌یابی.
- **نام‌گذاری خودکار گره‌ها** با تلاش برای افزودن نام گروه و میزبان یا IP.
- **ذخیره‌سازی تنظیمات در Cloudflare Workers KV**.
- **هشدار تغییرات ذخیره‌نشده** و نوار ثابت ذخیره‌سازی.

## پیش‌نیازها

- یک حساب Cloudflare
- یک فضای ذخیره‌سازی Workers KV
- یک رمز عبور قوی و اختصاصی برای داشبورد
- لینک‌های اشتراک یا URI کانفیگ‌هایی که مجاز به استفاده از آن‌ها هستید

نیازی به نصب Node.js یا ابزار خط فرمان Wrangler نیست؛ مراحل زیر از طریق داشبورد Cloudflare انجام می‌شوند.

## راه‌اندازی روی Cloudflare

### ۱. تنظیم رمز عبور

فایل `worker.js` را باز کنید و این خط را پیدا کنید:

```js
const DASHBOARD_PASSWORD = "CHANGE_ME_TO_YOUR_OWN_PASSWORD";
```

در نسخه‌ای که اجرا می‌کنید، عبارت نمونه را با یک رمز عبور طولانی و منحصربه‌فرد جایگزین کنید.

**نکتهٔ امنیتی مهم:** این مخزن عمومی است؛ رمز واقعی خود را در GitHub قرار ندهید. نسخهٔ عمومی کد را با همان مقدار نمونه نگه دارید و رمز را فقط در یک نسخهٔ خصوصی از فایل وارد کنید. در نسخهٔ فعلی، رمز در کد قرار دارد و هرکس به کد مستقرشده دسترسی داشته باشد می‌تواند آن را بخواند.

### ۲. ساخت Worker

1. وارد [داشبورد Cloudflare](https://dash.cloudflare.com/) شوید.
2. بخش **Workers & Pages** را باز کنید.
3. گزینهٔ ساخت برنامه را انتخاب و سپس یک **Worker** جدید ایجاد کنید.
4. نامی مانند `v2ray-subscription-hub` برای آن انتخاب کنید و Worker اولیه را مستقر کنید.
5. Worker را باز کنید و وارد **Edit code** یا **Quick edit** شوید.
6. تمام محتوای فایل خصوصی `worker.js` را جایگزین کد اولیه کنید.
7. تغییرات را ذخیره و Deploy کنید.

پس از استقرار، Cloudflare یک نشانی اینترنتی برای Worker ارائه می‌دهد. از این نشانی برای ورود به داشبورد استفاده خواهید کرد.

راهنمای رسمی: [ساخت Worker از داشبورد](https://developers.cloudflare.com/workers/get-started/dashboard/)

### ۳. ساخت فضای Workers KV

1. در داشبورد Cloudflare بخش **Workers KV** را پیدا کنید؛ ممکن است زیر **Storage & databases** باشد.
2. یک Namespace جدید بسازید.
3. نامی مانند `VPN_DB` برای آن انتخاب کنید.

### ۴. اتصال KV به Worker

1. به **Workers & Pages** برگردید و Worker خود را باز کنید.
2. به **Settings → Bindings** بروید.
3. گزینهٔ افزودن Binding را انتخاب و نوع **KV namespace** را مشخص کنید.
4. نام متغیر را دقیقاً `VPN_DB` قرار دهید.
5. Namespace ساخته‌شده در مرحلهٔ قبل را انتخاب و Binding را ذخیره کنید.
6. اگر از شما خواسته شد، Worker را دوباره Deploy کنید.

**توجه:** نام متغیر Binding باید دقیقاً `VPN_DB` باشد؛ نام نمایشی Namespace به‌تنهایی کافی نیست.

راهنمای رسمی: [مستندات Workers KV](https://developers.cloudflare.com/kv/get-started/) · [اتصال KV به Worker](https://developers.cloudflare.com/kv/concepts/kv-namespaces/)

### ۵. ورود به داشبورد

نشانی Worker را در مرورگر باز کنید و با رمز عبوری که تنظیم کرده‌اید وارد شوید. اگر ذخیره‌سازی کار نمی‌کند، ابتدا بررسی کنید که Binding با نام دقیق `VPN_DB` تنظیم شده باشد.

## استفاده از داشبورد

### ساخت گروه و افزودن کانفیگ

- گزینهٔ **Add Server Group** را برای ساخت گروه جدید انتخاب کنید.
- برای هر گروه یک نام معنادار وارد کنید؛ مثلاً Germany یا Finland.
- در حالت **Direct Configs**، URI کانفیگ‌ها را هرکدام در یک خط وارد کنید.
- در حالت **Subscription Links**، لینک‌های اشتراک HTTP یا HTTPS را هرکدام در یک خط قرار دهید.
- برای بررسی تعداد کانفیگ‌های دریافت‌شده از گزینهٔ **Sync / Count** استفاده کنید.
- برای ذخیرهٔ گروه‌ها و تنظیمات، **Save Changes** را بزنید.

فقط لینک‌هایی را وارد کنید که به آن‌ها اعتماد دارید و مجاز به استفاده از آن‌ها هستید؛ Worker این نشانی‌ها را از زیرساخت Cloudflare درخواست می‌کند.

### تنظیم ترتیب و چرخش

ترتیب گروه‌ها بر خروجی اثر می‌گذارد. اندازهٔ چرخش تعیین می‌کند در هر دور چه تعداد کانفیگ از هر گروه برداشته شود. برای نمونه، اگر اندازهٔ چرخش ۲ باشد، دو کانفیگ از گروه اول، سپس دو کانفیگ از گروه دوم و همین‌طور از گروه‌های بعدی برداشته می‌شود؛ سپس دور بعدی آغاز می‌شود تا همهٔ کانفیگ‌ها در خروجی قرار بگیرند.

### استفاده از لینک اشتراک

لینک تولیدشده در داشبورد را در کلاینت سازگار با V2Ray/Xray وارد کنید. خروجی پیش‌فرض Base64 است. برای بررسی دستی متن خام می‌توانید `?format=plain` را به لینک اشتراک اضافه کنید؛ برای استفادهٔ معمول در کلاینت، این پارامتر را حذف کنید.

با انتخاب **New code**، کد اشتراک شش‌رقمی جدیدی ساخته می‌شود و لینک قبلی بلافاصله از اعتبار می‌افتد؛ بنابراین لینک جدید را در کلاینت خود به‌روزرسانی کنید.

## قالب‌های پشتیبانی‌شده

پروتکل‌های شناخته‌شده شامل این موارد هستند:

`vless`, `vmess`, `trojan`, `ss`, `ssr`, `hysteria2`, `hy2`, `hysteria`, `tuic`, `wireguard`, `wg`, `socks`, `socks5`, `anytls` و `juicity`.

ورودی اشتراک می‌تواند فهرستی از URIهای متنی یا فهرستی با کدگذاری Base64 باشد. برخی قالب‌های اختصاصی یا غیرمعمول ممکن است به‌طور کامل بازشناسی یا نام‌گذاری نشوند.

## نکات امنیتی و محدودیت‌ها

- رمز داشبورد در نسخهٔ فعلی داخل کد قرار دارد. آن را در مخزن عمومی منتشر نکنید؛ استفاده از Secret یا متغیر محیطی Cloudflare برای نسخه‌های آینده مناسب‌تر است.
- در کد فعلی محدودسازی تعداد تلاش‌های ورود وجود ندارد؛ بنابراین آن را جایگزین یک سامانهٔ احراز هویت با امنیت بالا در نظر نگیرید.
- کد اشتراک شش‌رقمی است. لینک اشتراک را عمومی نکنید؛ هرکس آن را به دست آورد ممکن است بتواند محتوای اشتراک را دریافت کند.
- اگر لینک اشتراک افشا شد، کد جدید بسازید و لینک را در کلاینت خود به‌روزرسانی کنید.
- کانفیگ نمونهٔ داخل کد صرفاً نمایشی است و سرور واقعی نیست؛ پیش از استفاده، آن را با کانفیگ‌های خود جایگزین یا حذف کنید.
- محدودیت‌های سرویس به طرح Cloudflare و سهمیه‌های جاری وابسته‌اند؛ [محدودیت‌های Workers](https://developers.cloudflare.com/workers/platform/limits/) را بررسی کنید.

## عیب‌یابی

**تنظیمات ذخیره نمی‌شوند:** وجود KV Binding را بررسی کنید و مطمئن شوید نام متغیر دقیقاً `VPN_DB` است.

**گروه اشتراک هیچ کانفیگی نشان نمی‌دهد:** دسترسی‌پذیری لینک، نوع پاسخ و پشتیبانی از قالب کانفیگ را بررسی کنید. برخی سرویس‌ها به احراز هویت یا Headerهای خاص نیاز دارند که ممکن است توسط این اسکریپت پشتیبانی نشوند.

**کلاینت لینک را وارد نمی‌کند:** از لینک معمولی بدون `?format=plain` استفاده کنید و معتبر بودن کد اشتراک را بررسی کنید.
